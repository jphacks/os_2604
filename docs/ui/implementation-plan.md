# UI反映の進め方

参照デザイン：https://claude.ai/artifact/3whhpT5HvHAutGkch8W1zT#page-dcb81aee8d83

## ブランチ

- UI統合用：`codex/ui`。main `247f552` から作成。
- 各画面はこの親ブランチから作業ブランチを切り、PRの取り込み先を `codex/ui` にする。人間がマージする。
- 最初の反映：`codex/ui-history`。履歴一覧・今日の記録・週間の花・記録なし。
- 次の単位：オンボーディング、計測表示、結果／入力、設定、推移グラフ。親へ取り込まれた共通部品を次のブランチで利用する。
- mainへの統合はUI全体の確認後に行う。

## 維持するもの

- 現在のSwiftUI Liquid Glassタブバーとスライド動作・タブ切替。
- 保存済みの実測値とnull、出典表示、削除確認、AI生成前保存。
- 比較は今日を除く直近7日・有効記録3件以上。デザイン例の7日分蓄積条件へ自動変更しない。
- 中断／失敗記録は保存しない。品質不足の架空履歴を追加しない。
- Cの計測・AI内部、研究モードの有効化条件にはUI反映だけで変更を加えない。

## 段階反映の注意

- サンプルの測定値・日付・レポート文を実データとして入れない。
- 今週の花は日曜始まり、その日までの良好な記録がある日を1輪とする。同日複数回でも1輪。未来日は数えない。
- 取得できなかったキャラクター画像は仮の花アイコンで表示。元画像の受領後に差し替える。
- グラフ切替はグラフ画面実装時に追加する。動かない切替ボタンを置かない。
- 自動計測開始・体温範囲34〜42℃・研究モード設定・クラウドを示唆するエラー等、現行動作と異なる箇所は見た目だけで採用しない。
