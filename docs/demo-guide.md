## 2. 事前準備

### ビルド・インストール

README記載の手順：

```sh
flutter pub get
dart run build_runner build
flutter devices
```

- 署名：Git除外の `ios/Flutter/LocalSigning.xcconfig` を使う（Debug/Releaseのxcconfigが任意includeする）。自分の署名設定をここに置く。値はGitに入れない。
- STATE記載の環境：Flutter 3.47.7 stable / Dart 3.13.5。ShiFtは署名付きReleaseビルド後、`devicectl` でインストール・起動した（bundle ID `com.example.os2604`）。
- 統合版で実行したReleaseビルド／インストール／起動の手順は以下。`<DEVICE_ID>` は `flutter devices` で確認した端末IDに置き換える。

```sh
sh tool/flutter_with_xcode.sh build ios --release
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun devicectl device install app --device <DEVICE_ID> build/ios/iphoneos/Runner.app
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun devicectl device process launch --device <DEVICE_ID> com.example.os2604
```

署名設定済みのローカル環境で実行する。`tool/flutter_with_xcode.sh` は `flutter` をXcode指定付きで呼ぶラッパー（`xcode-select` は変更しない）。
- STATEの環境メモ（ShiFt環境）：SDK `/private/tmp/os2604-c-flutter`、`PUB_CACHE=/private/tmp/os2604-c-dart/pub-cache`、CocoaPods 1.16.2は `/private/tmp/os2604-c-gems`（`GEM_HOME`/`GEM_PATH`、`RUBYOPT=-rlogger`、binをPATHへ）。自分の環境では不要な場合がある。

## 3. 本番デモ手順

1. **初回説明**（初回起動のみ、画面「はじめに」）
   - 表示：データは端末内で処理、画像・動画は保存しない、診断目的ではない、撮影にはカメラ権限が必要。
   - 操作：「説明を確認して次へ」をタップ。
   - 期待：ホームへ遷移する。以後は再表示されない（ホームの「アプリの説明」から再表示可）。
2. **ホーム**（画面「15秒健康チェック」）
   - 期待：「本日はまだ記録がありません」（記録後は「本日は記録済み」）、「前回結果：…」が表示される。
3. **チェック開始**：「チェック開始」をタップ → 画面「15秒チェック」。
4. **カメラ許可**：初回は iOS の許可ダイアログが出るので許可する（出る時点は**要確認**。説明画面には「カメラを使う際に許可を確認します」とある）。
   - 期待：「カメラを準備しています」の後にカメラ映像と枠が出る。
5. **顔合わせ**：枠に顔を収め、正面を向いて動かない。
   - 期待：「顔を枠に合わせて、開始を押してください」。ずれると「顔を画面の中央に寄せてください」「少し暗いようです。明るい場所に移動してください」等のガイドが出る。
6. **15秒計測**：「開始」をタップ。
   - 期待：「計測中　残り N 秒」が減り、約15秒で終了。顔位置確認後の15秒で、準備時間を含まない。
7. **結果**（画面「結果」）
   - 期待：計測後すぐ「記録は保存されました。」。計測日時／計測時間／品質（良好／不十分／中断）／顔検出／心拍数／顔色特徴量／体温／体調の行が出る。
   - 心拍数は現状「未測定」（下記6参照）。「体温はカメラで測定していません」と表示される。
8. **体調・体温入力 → レポート作成**
   1. 「今日の体調（任意）」で1〜5を選び「体調を保存」。期待：「体調を保存しました」。
   2. 「体温（任意）」に外部体温計の値を入力し「体温を保存」（入力を消す場合は「入力を消す」）。期待：「体温を保存しました」、体温行が「◯ ℃（手入力）」に変わる。
   3. 「レポートを作成」をタップ（作成済みなら「レポートを作り直す」）。
   - 期待：レポート欄に定型文（「生成モード：定型文」で始まり、撮影品質・体調・心拍数・体温・「この記録は診断目的ではありません。」）。その下に「定型文で作成」と、理由（現状は「この端末では端末内AIを使えないため、定型文で表示しています」）。
   - 注意：体調・体温の保存は、生成中のレポートを破棄する（遅い応答は書き込まれない）。**先に入力してから**レポートを作る。入力後に保存済みレポートへ反映するには「レポートを作り直す」。
9. **ホームへ**：「ホームへ」をタップ。期待：ホームの「本日は記録済み」「前回結果：…　品質：良好　体調：N / 5」。
10. **履歴**：ホームの「履歴」をタップ（画面「履歴」）。
    - 期待：新しい順の一覧（日時、品質、体調。未入力は「未入力」）。タップで結果画面。ごみ箱アイコン（この記録を削除）で確認ダイアログ→「削除」。
    - 上部カード：今日を除く直近7日の有効記録が3件未満なら「基準値蓄積中（有効記録 N/3件）」。3件以上で体調が3件あれば「直近7日間（今日を除く）の体調の中央値：N / 5」。比較を見せるには、過去日に有効記録が3件必要。
    - 当日の記録は基準値に入らないため、デモ当日に連続計測しても比較表示にはならない。**要確認**（比較表示を見せる必要があるか、見せる場合の事前データ作成方法）。
11. **設定**：ホームの「設定」。期待：「毎朝の通知」スイッチ（初期はオフ）と「通知時刻」（HH:mm、オフの間は押せない）、「すべての健康記録を削除」、「このアプリは診断目的ではありません」。
    - 通知をオンにすると iOS の許可ダイアログが出る。許可で「毎朝 HH:mm にお知らせします」、拒否だとオフのまま「通知が許可されていません。設定アプリから許可できます。」。設定に失敗した場合は「通知を設定できませんでした（設定は変更されていません）」。オフにすると「毎朝の通知をオフにしました」。
    - 通知内容：タイトル「15秒チェック」、本文「おはようございます。今日の記録をつけましょう。」。タップでアプリが開く。
    - iPhone 15 / iOS 26.6.2 で通知の到着をユーザー確認済み。時刻変更・取消・タップ起動もユーザー確認済み。翌日の繰り返しは未確認。

## 6. デモで言わないこと・注意

- **診断しない。** 病気の診断・治療判断・緊急判定には使えないと必ず伝える。
- **心拍**：現状は未実装で値はnull、画面は「未測定」。「心拍を測れる」と言わない（将来出る場合も「試験的な推定値」）。
- **体温**：カメラでは測っていない。入力は外部体温計の手入力。
- **AI**：Swiftブリッジ未実装のため、現状のレポートは常に定型文。「AIが分析した」と言わない。AI実機動作は未確認。
- **通知（B-05）**：iOSネイティブビルド成功、iPhone 15で通知到着をユーザー確認済み。時刻変更・取消・タップ起動もユーザー確認済み（T08合格）。翌日の繰り返しとAndroidは未確認。
- STATE上の未確認：権限拒否・暗所・計測中の顔外れ・アプリ離脱・削除・機内モードの実機試験、Swift AIの実機動作。表の空欄を埋めるまで「確認済み」と言わない。
- 画像・動画は保存されない。健康記録は端末内にのみ保存される（外部送信なし）。

## 7. トラブル時

- **保存失敗**：スキャン画面に「記録を保存できませんでした。結果は保存されていません。もう一度保存を試してください。」と「保存を再試行」。再試行で同じ記録を保存する。結果画面の体調・体温・レポートの保存失敗は各ボタン下に「（保存されていません）」と出るので、再度ボタンを押す。
- **カメラが起動しない／映像が出ない**：「15秒チェック」画面を戻る（「カメラの映像を待っています」が続く場合も）→ホームから「チェック開始」をやり直す。それでもだめならアプリを完全終了して再起動。権限拒否なら iOS設定でカメラを許可。
- **履歴が読み込めない**：「履歴を読み込めません。再試行」をタップ。
- **レポートが定型文になる**：現状の正常動作。「定型文で作成」と理由が表示されていれば問題ない。
- 計測が失敗した場合：「再試行」で撮り直し。失敗した計測は履歴に残らない。
