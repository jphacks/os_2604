PROJECT  /  15-SECOND MORNING CHECK
アプリ仕様書  ―  MVP設計
版数 0.1  ｜  2026年10月17日  ｜  3名・2日間のプロトタイプ開発向け
プロダクトの一文定義
・毎朝15秒、顔をカメラで撮影して記録を残し、過去の自分との差をオフラインAIが説明する健康セルフチェックアプリ。
・医療的な診断、病気の検出、正確な体温・血圧測定は目的に含めない。

01  目的・対象・方針
対象ユーザー：自分の体調や生活習慣を毎日簡単に振り返りたいスマートフォン利用者。対象OSはiOS / Android。将来macOS・Windowsを検討するが、2日間では対象外。
価値：15秒で継続しやすい記録を作り、単日の「良い／悪い」を断定せず、睡眠・主観的体調・推定心拍などの経時的な変化を見える化する。
開発の基本原則
•  撮影時間は「顔位置確認後の15秒」。準備時間とAIの文章生成時間は含めない。
•  推論は端末内で完結させる。OS標準AIが利用できない場合は定型レポートに切り替える。
•  画像そのものは原則保存せず、必要な集計値だけ端末に記録する。
•  測れないものは「未測定」とし、推定値・サンプル値を医療的な実測値として見せない。

03  利用フロー（ユーザー視点）
初回設定（撮影の説明／権限／通知時間）    ↓ 毎朝のローカル通知 → アプリ起動 →「チェック開始」    ↓ 顔の位置・明るさを確認 → 15秒カウントダウン    ↓ 顔の検出／計測品質を集計 → 体調1〜5を任意入力    ↓ 測定結果を先に保存 → 過去の記録と比較    ↓ Apple Foundation Models / Gemini Nano で短いレポート作成    ↓（AI不可なら定型文章） 結果画面 → 履歴画面 → 翌朝の再通知

例外的な動作
•  カメラ権限なし：理由を説明して設定画面への案内を表示。
•  顔を検出できない／明るさ不足：15秒の計測を始めず、位置調整の案内を表示。
•  途中で顔が外れた・アプリを離れた：測定結果を「無効／中断」にし、再試行を提案。
•  AIが未対応・初期化中・制限発生：データを保存し、AIなしの定型レポートを表示。
•  初回や履歴不足：過去データとの比較は行わず「基準値蓄積中」と表示。

05  計測・AI処理の設計
計測レイヤー（リアルタイム）
Cameraプレビュー → ML Kit Face Detection（顔の有無と特徴点） → 明るさ・向き・顔の安定性などの品質集計。必要であれば頬・額のRGB特徴量を一時取得する。MediaPipe Face Landmarkerは顔形状の詳細解析が必要になったときの追加候補。
rPPGの取り扱い
POS / CHROMなどで顔の色の時系列から脈波を抽出する方式を調査する。ただし、15秒間のRGB動画から心拍数を常に正確に推定できる保証はなく、照明・動作・機種・肌色等で誤差が変動する。2日間では「研究／実験モード」に限定し、基準心拍計で比較するまで医学的・健康判断に使用しない。
分析レイヤー（撮影後）
過去7日程度の有効記録の中央値などをDart側で計算してからAIへ渡す。AIの担当は「数値の説明」と「記録の振り返り」に限定し、病名の推測・体温の創作・医学的な緊急判定をしない。短い箇条書きレポートを返す。
オンデバイスAIの分岐
・iOS：Apple Foundation Models（対応端末でのみ）。
・Android：ML Kit GenAI Prompt API / Gemini Nano（対応機種・モデル準備が必要）。
・非対応・初回モデル未準備・OS側の推論制限時：テンプレート文を生成するフォールバック。

06  共通データ仕様・受け渡し
B担当とC担当の接続形式。計測結果に偽の数値を入れないため、未測定の値はnullにする。以下は概念的なDartデータモデル（フィールド名は実装開始時に固定）。
HealthCheckResult {   id: String, measuredAt: DateTime, durationSec: 15,   faceDetected: bool, quality: good | poor | interrupted,   estimatedHeartRateBpm: double?,  // rPPG試験機能のみ   heartRateSource: rppgExperimental | external | none,   faceColorFeature: double?,       // 外観の色特徴量、診断値ではない   selfCondition: int?,             // 本人入力 1..5   bodyTemperatureC: double?,       // 外部体温計や連携データ   temperatureSource: manual | healthPlatform | none,   reportText: String?, aiMode: onDevice | template }

データ保存とアクセス
•  保存先：Drift / SQLite。カメラ映像はメモリ内で処理し、動画・静止画像を既定では永続化しない。
•  レポート生成が失敗しても計測結果は失わないよう、測定終了直後に保存する。
•  データ削除を提供し、分析画面で取得元（撮影・手入力・健康プラットフォーム）を表示する。
•  健康情報のため、公開前にはDB暗号化・バックアップ方針・プライバシーポリシーを別途整備する。

08  非機能要件・受け入れ基準
分類
検証観点
オフライン
セットアップ後の機内モードで撮影／保存／定型レポートが動く。AIは利用可否に応じ分岐。
時間
顔の位置確認後、15秒計測を行う。開始・中断・再試行を操作できる。
プライバシー
ネット送信を既定で行わず、無断で写真・動画を保存しない。
結果の誠実さ
測定できない値は「未測定」。体温をRGB画像から算出しない。
エラー対応
権限拒否、顔未検出、AI非対応でクラッシュしない。
動作確認
利用可能な実機で再現できるデモ動線を1本以上確保する。

安全・公開上の注意
・アプリは日常の記録と変化の説明を目的とし、健康／疾病の診断、緊急アラート、治療判断を行わない。
・測定精度は実機・複数条件・基準計測器との比較で検証が必要。2日間の完成物は「検証用MVP」。
・ストア公開前に健康測定の根拠開示、プライバシー、医療機器プログラムの該当性を確認する。

09  今回は実装しない／将来の拡張
•  通常カメラから体温・血圧・SpO₂を測定する機能。体温は手入力か既存の健康データを使用。
•  複数人の顔の同時測定、長時間バックグラウンド撮影、自動で病気を検出する機能。
•  iOS / Androidの両方のオンデバイスAIを2日で完成させることを必須にしない。先に対応実機1台で動かす。
•  macOS・Windowsアプリの配布、アカウント登録・クラウド同期、ストア公開手続き。
