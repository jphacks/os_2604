## 2026-10-17 cブランチの互換性修正

- ユーザー回答：現在の開発フェーズはDay 1。
- ユーザー承認：旧DBの日時は「2026年の秒値だけ変換する」。UTCの2026-01-01以上・2027-01-01未満に相当するUnix秒値を100万倍し、マイクロ秒へ統一する。その他の値は保持する。新しい入力日時を2026年に制限する仕様ではない。
- 旧v2と通知追加後のv3には秒・マイクロ秒の単位情報がない。現行のマイクロ秒値を一律に変換せず、schema v4への移行で上記範囲だけを更新する。範囲外の旧秒値や、同じ整数値になる1970年付近のマイクロ秒値の完全判別はできない。別の期間への対応は追加判断が必要。
- 移行はテーブル追加と日時更新を同じトランザクションに含める。失敗は呼び出し側へ返し、既存記録を削除・初期化して回復しない。記録のID・任意入力・NULL・本文・生成モード・説明確認・既存通知設定を保持する。
- カメラ権限確認は計測前に行う。共有進捗へ`requestingPermission`を追加し、利用側の撮影画面も同時に更新する。この状態での一時的な`inactive`だけは待機し、背景化・画面離脱は引き続き中断する。カメラ初期化は許可と前面復帰の後に行い、実計測の15秒と初期化の10秒制限にOSダイアログの待ち時間を含めない。

## 2026-10-18 E84室温・湿度（ユーザー承認）

- 実装計画の推奨案を採用し、新機能を実装できる時間枠であると回答あり。今回の対象はブランチ内の実装・検証まで。iPhone／キットへの更新は行わない。
- Find MeのIASと1接続を共用。環境取得は既定OFF、前景の約2秒周期、Read上限2秒、20バイトlittle-endian v1、鮮度上限5秒。LEDの送信・点灯中は新規環境Readを抑止して消灯期限を優先する。進行中のReadは取り消せると仮定せず、timeoutは同じ接続を破棄する。
- 専用UUID：Service `3c1d0001-8e4b-4b1c-9a62-6d485a7e9010`、Read characteristic `3c1d0002-8e4b-4b1c-9a62-6d485a7e9010`。公式UUIDではない。ファームウェアとDartの対応を試験する。
- 受信時の長さ・版・状態・予約領域・ペア範囲を検査。正常以外は両値NULL、未知版／予約領域は環境未対応としIASは維持。鮮度はsampleAge＋Read往復時間＋受信後経過を単調時計で計算。計測成功直後に固定し、DB再試行や結果遷移で別値へ交換しない。
- 健康記録のINSERT成功後、アプリ所有の保存サービスが環境スナップショットを同じIDへ関連付ける。環境保存だけの失敗は別表示・同じ固定値で再試行。環境値を体温、AI入力、健康の基準値へ追加しない。
- DB：別worktreeのv6起動修正と互換モデル／保存層を最小範囲で取り込み、次の未使用版v7で `health_record_environment` を追加。時間の精度を保つため、受信日時と終了時の推定経過時間はいずれもmicroseconds単位で保存する。外部キーを毎接続で有効化し、親存在確認と関連付けは1トランザクション。個別／全件削除でCASCADEする。既存環境行は上書きしない。
- センサー依存版・ファームウェア適用差分・ビルド情報は `firmware/e84/environment*` に固定。既存LED用プロジェクトと復旧イメージを保持。実機の受け入れ状況は `docs/e84-environment-demo.md` に区別して記載する。
