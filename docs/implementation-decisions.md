## 最初の30分で固定する契約と合意状況

1. **対象実機とOS（ユーザー決定済み）**：正式対象はiPhone 17 / iOS 27以降。SDKはFlutter 3.47.7 / Dart 3.13.5。
2. **計測時間の所有者（合意済み）**：Cの単調時計で15秒を判定し、Bは進捗を表示する。独立したUIタイマーで成功判定しない。
3. **結果と失敗の型（実装済み）**：`ScanOutcome` の成功／失敗を分離。成功は `HealthCheckResult`、失敗は理由と実経過時間。`HealthScanService` が開始・進捗・キャンセル・解放を提供する。
4. **時間・品質の記録（暫定設定を承認）**：目標は15秒、実経過は `Duration elapsed`。品質閾値はDay 1設定を仮採用。
5. **保存と追記（一部未決）**：Bは成功結果を直ちに保存し、同一IDへ自己申告・体温・レポートを追記する。中断記録は保存しない。
6. **比較の条件**：端末ローカルの今日を除く直近7暦日から有効記録を使い、3件以上で比較する。不足時は「基準値蓄積中」。
7. **削除と非同期更新**：健康記録の個別削除と全件削除を提供する。

## 2026-10-17 ユーザー承認済みの保存・履歴仕様

- 中断・失敗は健康チェック履歴に保存せず、再試行を案内する。
- 自己申告がなくても、有効な計測結果だけで保存する。
- 健康記録の個別削除と全件削除を提供する。
- 端末ローカルの今日を除く直近7暦日から有効記録を使い、3件以上で比較する。不足時は「基準値蓄積中」。

## 仕様を読むときの注意

- アプリ仕様書は初回設定を含む6画面を列挙し、分業書は主要5画面をAの成果物としている。画面数の呼称にかかわらずP0の初回説明・権限導線を落とさない。
