## 最初の30分で固定する契約と合意状況

1. **優先実機とOS**：機種・OS・利用可能なAIを確認する。AI不可でも定型文でデモ成功という文書の基準を共有する。
2. **計測時間の所有者（合意済み）**：Cの単調時計で15秒を判定し、Bは進捗を表示する。独立したUIタイマーで成功判定しない。
3. **結果と失敗の型（実装済み）**：`ScanOutcome` の成功／失敗を分離。成功は `HealthCheckResult`、失敗は理由と実経過時間。`HealthScanService` が開始・進捗・キャンセル・解放を提供する。詳細はC接続メモ参照。
4. **時間・品質の記録（暫定設定を承認）**：目標は15秒、実経過は `Duration elapsed`。品質閾値はC接続メモ記載のDay 1設定を仮採用。実機での妥当性・調整結果はこれから確認する。
5. **保存と追記（一部未決）**：Bは成功結果を直ちに保存し、同一IDへ自己申告・体温・レポートを追記する。生成前の本文・AIモードはnull。中断記録を保存するか・どの形式で履歴に残すかは引き続き未決で、成功記録として保存しない。
6. **比較の条件**：「過去7日程度」の期間、最低件数、有効記録の条件、当日結果の扱いを決める。未測定と実験心拍を通常の健康評価に混ぜない。
7. **削除と非同期更新**：全記録削除／個別削除の提供範囲、生成途中に削除した記録をAI応答で再作成しない扱いを決める。

## 仕様を読むときの注意

- アプリ仕様書は初回設定を含む6画面を列挙し、分業書は主要5画面をAの成果物としている。画面数の呼称にかかわらずP0の初回説明・権限導線を落とさない。
- 通知はP1。初回設定の通知拒否でP0を止めない。OS制約下での通知精度・翌日以降の更新方法は実装時に確認する。
- 両OS対応が目標でも、時間不足時に実機のあるOSへ集中する切替えが分業書で認められている。実際に保証するOSと未検証範囲を記録する。
